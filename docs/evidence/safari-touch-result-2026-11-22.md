# Safari 手机预览首次触屏退出

日期：2026-11-22

用户设备为 iPhone 15 Plus / Safari。扫码开始游戏后触屏会返回开始页，错误为 `pointerId must be an integer from 0 to 1000000.`。

根因为浏览器指针编号与 Engine Replay 的编号范围不一致。预览输入桥原样传入 Safari 的较大编号，运行时输入校验拒绝该事件并报告错误；手机页面收到运行错误后销毁游戏，返回带工程名称的开始页。这与二维码、证书或游戏名称无关。

`pointerId` 是浏览器分配的指针标识，不能假设它很小或从 1 连续递增；[W3C Pointer Events](https://www.w3.org/TR/pointerevents3/#dom-pointerevent-pointerid) 使用长整型，并允许浏览器采用不同分配策略。

在 DOM → Replay 的输入桥增加每个运行环境独立的编号映射。合法且未冲突的编号保持不变；较大编号映射为合法的空闲编号，整次按下、移动、抬起或取消期间保持稳定。不同手指及鼠标的活动编号不冲突；结束后释放编号，失焦和销毁清空映射。活动指针上限 64，重复触屏复用编号，不按 Safari 编号无限积累。滚轮也使用同一映射规则。

Engine 公共包、Replay 输入格式、数值校验和项目脚本均保持不变。画布增加 `touch-action: none` 与禁止文本选择，避免手势由浏览器接管。手机页面对真实运行错误的处理保持不变。

旧构建在回归中准确重现相同提示及 `playing → stopped`。重建后相同测试通过：在真实 Chromium HTTPS 隔离运行页，使用可信触屏事件，并在 DOM 属性边界呈现 Safari 量级编号；检查按下/移动/抬起、双指、取消、映射后编号范围、游戏保持运行，以及随后鼠标操作、重玩和服务撤销。没有直接从模拟层注入事件，也没有取消 Engine 校验。

定向普通检查 10 项通过，原生 HTTPS 触屏/鼠标检查 1 项通过。用户随后在 iPhone 15 Plus / Safari 确认手机扫码运行正常；代理自身没有连接实体 iPhone。

能力检查 20 组、395 项全部通过。`npm run check` 前置全部通过，89 个集成文件共 527 项，526 项通过、1 项失败，无跳过或取消。唯一失败仍为 large 产品窗口的既有硬件冻结断言：要求 i7-7700 / 8 线程，当前为 i7-14700KF / 28 线程；没有放宽断言或推进里程碑。七类游戏回放及新增触屏回归均通过。生成证据敏感信息扫描通过（688 个文件、406,280,005 字节）。

源码输入摘要为 `sha256:087954705a58498137afd698b1c40f96ac786f428f4572e5fc3d839382aa46ef`。原始对照日志及完整检查归档在 `.cache/safari-touch`；受控 test-output 已恢复历史基线。
