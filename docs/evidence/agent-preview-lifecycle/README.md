## 当前魔方的证据

读取当前项目的持久执行记录（document r5）及成功提交的脚本，而非未应用的 proposal：

- 27 个 rounded-box 共用近黑色 `[0.055, 0.065, 0.08, 1]` basic 材质，没有独立的彩色面。basic 是不受光照影响的材质，因此加灯不能修复这一外观。

- 控制脚本只更新 component.data 内的 turn、orbitX、orbitY，并调用 hudText / observe。没有把这些变量应用到实体或活动相机的真实变换。
- 通过 `x ∈ (0.28, 0.72), y ∈ (0.2, 0.8)` 的固定屏幕矩形判断命中，没有配置/消费引擎的指针交互命中。
- 编辑视口的 OrbitControl 不会自动进入游戏预览。
- 当前项目的执行记录没有 play.stop 调用。编译、启动成功与脚本上报计数不能证明用户要求已实现。

## 通用修复路径示例

对于有不同颜色表面、多个移动部件和重复结构的物体：

1. 把外观拆解为轮廓、着色表面、交互面和共同运动父节点。先完成一个组合并实际预览，再保存 prefab 和复制。魔方可使用圆角主体加六个有独立颜色的圆角薄片；部分不可见内表面可按需求省略。
2. 给可交互实体配置 haiyue.interaction.pointer，用 api.input.interactions() 的 entityId 和世界 hit.point 判断目标，转换到对象的局部逻辑坐标。pointerEvents 的 x/y 是左上原点的画布归一化坐标，不是世界坐标。
3. 拖动目标时更新真实部件变换；拖动背景时更新真正活动的游戏相机。逻辑状态、画面变换和观察数据保持一致。
4. 调用 play.inspect 取基线，注入拖动，再比较 state.entities 中按 id 匹配的实体 position / rotation / scale 数组。对层旋转检查选中层改变、其他层不变；对背景拖动检查活动相机改变。数组数值遵循引擎运行时表示，不按编辑器的 rotationDegrees 猜单位。
5. 使用同帧 play.capture 检查可见颜色、圆角、构图和运动结果。gameplay[].value 是脚本上报数据，只能辅助验收，不能单独证明真实运动。
6. 最后调用 play.stop；失败后修复前同样关闭测试预览，保留证据再进行下一轮。

工具说明与按需交互/视觉 playbook 已补充上述要点。它们降低相同误用的概率，不构成对模型未来生成质量的保证。

## 预览生命周期

Agent 预览按项目和 taskId 持有，跨 provider turn 和审批等待保留；测试进入 evaluating / repairing、任务 completed / failed / cancelled / blocked、项目切换或所属任务消失后自动释放。手动预览不被旧任务关闭。测试时显示提示，禁用手动输入、暂停及设备调整，允许显式停止所属任务后退出。停止/清理事件按 previewId 同步 broker，迟到的旧实例清理不影响新实例。

只读运行检查与 Agent 工具共享预览通道：inspect / capture / physics-query 可以读取手动预览，但不会接管归属；Agent 的 step / input 与自动关闭仍受归属限制。原生产品流程已验证手动预览观察、源码定位及项目历史读取。
