# 预览指针、分阶段验收与棋盘贴图

2026-09-14。本记录针对 AIStudio 产品代码，未重启用户应用，未改写已有项目或历史任务的验收结果。

## 查明的原因

用户任务的保留证据包含 9 步落子、黑方获胜、`state: won`，运行错误计数为 0。审批后的条件同时要求初始 `playing` 和最终 `won`。旧求值器总是使用同类最新证据，因而把已经获胜的快照用于检查初始状态。反复求值耗尽修复预算后，同一 turn 中较早排队的继续修复请求仍被执行；后续 `play.inspect` 又尝试将 blocked 切到 playing，用 `task.transition-invalid` 覆盖了原始阻塞诊断。

棋盘 PNG 已生成且 `asset.assign` 成功。自动新增的 PBR 组件却使用默认蓝色 `[0.16, 0.58, 1, 1]`。预览使用该组件，而编辑视口只使用旧 appearance，因此显示不同。图片还以父页面 Blob URL 交给隔离预览，未在预览本地建立可加载的数据源。

## 完成的修改

- 外层虚拟指针直接订阅 Agent 发给预览的归一化输入，显示移动、按下、拖动、抬起、取消和滚动；短暂保留按下/抬起标记，缩放时与 iframe 共用坐标范围。它不接收输入、不移动 iframe、不进入游戏截图；停止/关闭时释放 DOM 和计时器。
- `task.evaluate.acceptanceEvidence` 可为审批后的每条条件选择对应阶段的已保留证据。未选择时保持最新证据语义。所有引用仍须属于同一 Play、修订、脚本、视口和设备，且满足当前修订与截图/状态配对校验；不能遗漏或重写审批条件。
- 终止验收会清理排队的继续请求，终态也不能启动自动继续。检查与停止工具不重启验收生命周期，保留原始诊断；通过项的空诊断不再错误地显示 `evaluation.result-missing`。
- 新增 base-color 贴图绑定使用白色因子；已存在的 PBR 保留显式颜色。手动及 Agent 材质编辑同步生效的 PBR 参数，切换为其他材质会禁用 PBR 覆盖，History 可撤销/重做。
- 编辑与预览使用同一材质运行适配器。编辑视口只安装材质描述符，不运行脚本、音频或游戏逻辑。纹理通过受控 Blob 数据传递，在使用页面本地解码；等待 Engine 上传，按槽选择 sRGB/线性格式。多个使用者共享解码源，保持 CPU 图片到最后一个使用者释放，以支持 Engine 设备恢复。
- 工具说明与可检索的 `play-evidence` / `presentation-effects` 文档补充了分阶段验收、坐标空间及颜色因子说明。

- `cursor.png`：实际完成绘制的指针与操作标记。游戏截图 `preview.png` 不含外层指针。
- `build.log`：产品构建成功。
- `root-check.log`：总检查停在既有能力验证记录的输入绑定过期；未手工改写能力记录，也未宣称总回归全绿。

窗口测试早期并行保留两个 WebGPU 视口时有初始化等待；最终按应用切换顺序释放编辑视口再创建预览，并通过逐帧推进采样。测试容器在 iframe 创建之前布局，避免移动 iframe 导致重载。

## 已有项目

旧蓝色 PBR 因子是项目数据，不能仅凭颜色猜测用户是否有意染色，因此没有自动迁移。对于本例，更新应用后将棋盘 PBR 基础色设为白色，即可保留 PNG 自带的黄色。历史失败不改成通过，应重新采集初始和最终状态，并按条件分别引用后验收。
