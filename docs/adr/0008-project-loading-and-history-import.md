# 工程加载反馈与历史导入

日期：2026-11-22。保持当前里程碑状态。

用户打开工程时只有页脚状态，无法判断较长的历史恢复是否仍在进行。桌球工程只读副本的测量显示：97,113 字节工程文件读取约 9 ms；首次向空编辑器缓存恢复项目历史约 13,039 ms，其中逐条日志追加约 8,550 ms，重复工件复制也有明显开销。会话内容恢复约 153 ms（离线后端，不含真实模型连接），同一缓存再次同步约 175 ms。主要优化对象是可移植历史首次导入。

Renderer 的 ProjectLoading 拥有一个不定进度遮罩。先绘制反馈，再执行打开/新建工程操作；保留到刷新后的绘制帧。加载时现有工作区为 inert、aria-busy；重复操作共用当前 Promise。成功、文件选择取消和错误均恢复既有状态与焦点；销毁恢复界面并阻止迟到结果再次写入。支持屏幕阅读器状态和 reduced-motion，不显示虚假百分比。

OperationLog 新增私有 workspace 内使用的 importEvents，用于已验证、已有项目归属的日志复制。每次最多 128 条，按段大小及 1 MiB 分组，重新校验/脱敏并保留事件 ID、时间和来源，使用目标日志的连续 sequence。组内全部工件就绪后，写入并同步整个组，再更新内存索引、通知复制观察者和返回结果。它复用正常追加的验证、序列化、配额、轮转及错误降级；普通工具事实继续按原 flushPolicy 追加。导入失败可以保留已持久化的前缀，重试按 eventId 校验去重，不回放任何 Document mutation。

项目历史导入在本次恢复范围内去重工件图：最多缓存 8192 个已验证地址；8 个 worker 复制独立工件，in-flight Promise 合并相同地址，所有 worker 结束后才发布该组日志或返回失败。每份工件仍验证内容摘要并原子落盘；缺失必需工件、篡改、不同项目归属和事件冲突继续拒绝。缓存不跨导入复用，不改变常规读工件的校验，也不改变项目长期日志保留策略。

同一份桌球日志副本的优化后首次同步约 2306 ms，比该次基线减少约 82%；日志写入组由 4764 次单条追加变为 38 次导入调用，独立工件写入由 2971 次降为 1440 次。同缓存再次同步约 115 ms。数据为本机单次对照，不代表任意工程的整体加载时间；两份输入 journal 哈希一致，原桌面工程保持原样。

IPC 记录 project/load-performance：只包括固定操作名称、结果及 prepare/document/history/total 耗时，不记录路径、项目内容或凭据，用于后续区分文档读取、旧工程释放和会话恢复的耗时。文件选择器耗时不计入这些阶段。完整验证与采样见 evidence/project-loading-result-2026-11-22。
