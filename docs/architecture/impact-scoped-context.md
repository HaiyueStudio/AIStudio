# 按影响范围获取创作上下文

AIStudio 的初始上下文是发现入口，不是全场景快照，也不声明任务只影响当前选区。

- 有选区：最多 8 个实体，读取 `hierarchy/components/scripts`，首批最多 64 项。
- 无选区：只读 `hierarchy` 的第一页，最多 32 项。先找到目标，再读取组件。
- 脚本投影只含元数据和摘要；源码由 `script.get` 按需读取。
- 场景投影预算 16 KiB，超预算重新查询更小的分页，保留查询服务生成的真实游标。
- 单项仍过大时返回明确的 deferred 状态和查询建议；不截断 JSON，不把省略当成空场景。
- 总提示词预算仍为 96 KiB。装配时先移除完整的可选知识命中，再延迟场景详情；必要内容仍超限则报告实际字节数。

## 影响范围逐步扩展

用户说“给按钮加一个自身呼吸动画”，应先解析目标，再读取它的 Transform、脚本绑定与相关源码。例如：

```json
{"revision":12,"scope":{"entityIds":["entity:button"]},"projection":["hierarchy","components","scripts"],"limit":32}
```

如果脚本只改变自身局部缩放，这些数据通常足够。如果需要跟随父对象、操作另一个对象或修改共享状态，应根据查询结果中的 parentId、组件引用和行为关系，追加相关实体：

```json
{"revision":12,"scope":{"entityIds":["entity:panel","entity:controller"]},"projection":["hierarchy","components","scripts"],"limit":32}
```

未知目标先分页查询层级，或使用 `scope.componentTypes` 定位候选，再请求候选实体的组件。沿 nextCursor 翻页时必须保持 revision、scope 和 projection 相同；修改查询条件时从第一页开始。父子关系不会被 entityIds 自动展开，需根据实际依赖补充。

`assets/camera/render/settings` 是全局投影，即使提供 entityIds 也不会限制到该实体。只有任务涉及对应全局系统时才请求它们。涉及碰撞、共享资源或全局玩法时，局部读取不足以证明没有其他影响；应通过现有 `behavior.query` 等工具定位关联并扩大验证范围。

模型负责结合用户意图和读取到的事实决定下一次查询。宿主不使用游戏种类或“自身”关键词推断安全边界，也不会自动遍历整张依赖图。

## 会话与增量

只在工具合同一致、项目/文档和查询范围一致、前次已确认发送且投影完整时使用增量。分页未完成、范围改变、增量过大或历史不可用时重新建立有界快照。

本地 CAS 命中与模型会话缓存分开计算。只有已开始的提供者 turn 在提交时确认收到的 artifact 才允许后续 reference-only。准备失败或仅准备未提交的上下文不更新会话基线。重启、工具合同改变后仍发送完整的当前局部入口，而不是全场景。

此预算约束覆盖宿主的初始 prompt 装配。模型后续工具结果仍受各工具的独立返回预算约束；不能据此保证长会话的提供者上下文永不达到其上限。
