# 贴图网格与交互落点对齐 / Textured grid alignment

For boards, tilemaps and placement surfaces, define ONE layout: intersection count, texture width/height, first/last line pixel centers, surface dimensions, UV orientation and board transform. Generate texture lines AND logical snapping/rendering from this layout. N intersections have N-1 intervals, never N. Pixel-to-local coordinate on a centered unmodified UV surface: localX=(pixelX/textureWidth-0.5)*surfaceWidth; spacing=(lastPixel-firstPixel)/(count-1)/textureWidth*surfaceWidth. Verify which surface axis follows texture v; invert it when needed. For a 16-unit centered board and 1024px texture with 15 lines at 64,128,...,960: origin=-7, spacing=1. Lines at 16,80,...,976 instead produce 16 intersections, origin=-7.75 and spacing=1; if the surface is 15 units, spacing becomes 0.9375. These are different grids and changing the anchor alone cannot fix spacing. api.input.interactions().point is WORLD space; use the engine transform inverse for a moved/rotated/scaled board, snap in board space, then transform marker positions back to world space. Never infer screen-to-world scale. Test actual center and corner intersections by projecting target points, simulating clicks, and inspecting resulting grid index AND rendered marker position. A passing move counter/win rule does not prove texture alignment. Use asymmetric corner marks to check UV flips. Reference example:grid-placement before writing a textured board script.
