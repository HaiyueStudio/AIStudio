# 桌面通知与提示音

在设置中的“通知与声音”可以分别开启系统通知、提示音和“仅在后台提醒”，并发送测试通知。三个开关默认开启，偏好按设备保存在 Electron userData 的 `preferences/notifications.json`，不写入项目。测试通知允许前台触发，每三秒最多一次。

需要权限审批、确认计划、补充信息，以及任务完成、失败或阻塞时触发通知。任务终态取自已有任务读模型；单次模型回复结束、工具失败和用户取消不会被当作任务完成。打开旧项目、恢复历史记录不会补发通知；已解决、过期或切换项目的提醒会撤回。重复事件去重，同时最多保留四条，单条最多五分钟。

点击通知会恢复并聚焦编辑器，校验当前项目后定位对应审批卡片或任务。点击不会替用户批准权限、回答问题或继续任务。通知文本只包含固定的事件类别，不包含项目名称、用户提示、工具参数或路径。

`agent-orchestration` 的 `ConversationAttentionTracker` 负责从已有会话读模型识别状态变化。应用层的 `DesktopNotificationService` 管理本地偏好、通知生命周期和点击目标；`electronNotificationPort` 提供系统通知和窗口效果。Shell 只负责展示和定位。订阅、通知和计时器均由应用根生命周期释放，通知故障不会改变任务结果。

Windows 使用应用自己的 AppUserModelID 和开始菜单快捷方式注册通知身份。提示音使用系统通知声音，受系统音量、通知及勿扰设置控制；发送失败时可通过任务栏闪烁提示，窗口重新获得焦点后停止闪烁。网页环境显示不支持桌面通知。自动化回归通过 `HAIYUE_STUDIO_DISABLE_NOTIFICATIONS=1` 隔离实际系统通知；真实系统通道另由显式运行的 `notification-native-main.mjs` 验证。

回归覆盖历史静默、去重、任务终态、审批撤回、项目切换、静音持久化、IPC 输入校验、真实窗口设置、键盘焦点及卡片/任务定位。真实 Windows 测试记录系统的 `show` 回调；此记录不代表人工听到了声音或点击过系统弹窗。
