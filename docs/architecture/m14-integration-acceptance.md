## 本次发现并修复的问题

- 行为结构与执行拓扑共用视图拖动逻辑：左键或中键可在空白处和节点上平移，拖过阈值后拦截节点单击，轻微抖动仍保留点击选择；缩放后的移动距离按屏幕像素计算。滚动条、键盘与缩放入口保留，节点选择刷新时保留查看位置，松手、取消、重绘和卸载释放指针捕获及监听器。两个真实 Electron 窗口覆盖未选节点拖动、中键、点击、防误选和取消。

- 试玩检查失败后再次验证预览，会在工具登记开始前抛出阶段异常；空批次随后先完成、后开始，导致 `session.sequence-gap` 覆盖原始错误并留下等待中的工具节点。阶段检查已移入受保护的工具执行流程，重复验证保留当前修复阶段；批次与取消结果等待开始记录，批次清理幂等且保留原始异常。五项新增真实持久化回归覆盖该顺序、普通/事务修改的阶段拒绝、空批次、取消迟到执行及重复收尾；用户历史日志不被改写。

- 象棋任务拓扑停在旧会话的两个可见节点，而实际后续会话已有 129 个节点。界面现在按真实执行时间排序并默认跟随最新阶段，手动查看历史时保留选择；阶段选择显示步骤数，重启恢复读取任务历史中先前使用的会话，已经为待确认审批打开的会话也纳入图投影并持续更新。恢复范围与既有界面上限统一为最近 50 个会话，不重放工具修改。
- 拓扑的“适应视图”原来仅重置到 100%，图区域的最小高度还可能把滚动条裁在外层容器之外。现在测量实际视区后整体缩放节点文字、连线和点击区域，保留用户滚动位置；完整记录/层级列表及键盘定位会展开目标并滚动到可见范围。归属连线以浅色虚线显示，全部/可见步骤数明确。真实窗口回归验证桌面与窄窗口、自动跟随、手动历史选择、滚动保持和屏幕外定位；测试驱动隐藏窗口后等待绘制帧的超时单独保留为失败证据，驱动时序修正后原有断言与超时预算保持。
- 用户象棋项目的 `codex.thread-toolset-drift` 来自按阶段重新选择工具后仍复用旧会话。上下文运行时现在与两个 Backend 共用工具指纹，比较有序工具 ID、说明和完整参数 schema；变化时发送完整策略、当前项目快照及可见历史/已确认计划，工具合同一致才复用会话与增量上下文。启动前失败不把合成会话标记为可复用，恢复来源不明的工具合同也保守重建。两个 Backend 原有漂移拒绝和工具权限检查继续保留。专项回归通过真实生产适配器配合本地模拟 transport，验证持久化审批后切换工具只执行一次已批准修改，不替代在线模型验收。
- 用户执行记录中的两次 `studio.plan.propose` 失败，来自自然语言验收条件不符合证据断言语法。计划工具现在明确说明语法、JSON 期望值、观察信号路径及通用示例；错误定位到 `acceptance[index].assertion` 并提示保留原要求进行修正。计划校验复用实际 evaluator 的解析器，未加 JSON 引号的字符串等不可执行断言在审批前被拒绝；不把自然语言静默降级成“有一份证据即通过”。
- 用户确认计划后的 `conversation.operation-failed / Tool catalog query is invalid`，来自内部工具选择把完整计划传入最多 512 字符的公开短搜索接口。现在内部选择与公开搜索共享排序实现，内部接受完整计划及尾部要求，公开搜索仍保持 512 字符约束；使用真实目录覆盖了持久化计划挂起、确认和续跑。
- 执行记录中的 `barrier.waiting-user` 表示为等待确认保存检查点并释放调用。记录查看器识别该明确返回值并显示“已挂起（等待确认）”，保留原始 `cancelled` 审计状态；真正取消仍显示“已取消”。读取失败可重试，切换项目后丢弃旧请求结果。
- 预览命令入队后只依赖周期唤醒，且已取消请求可能永久等待。Broker 现在通过原有 renderer 通知通道即时唤醒，并在入队前拒绝已取消请求，订阅仍归同一根释放。
- 真实 Play 观察携带未加 `sha256:` 的脚本摘要，被原合同拒绝；现在在生产 renderer 入口统一成既有摘要格式。
- 公共高级面板的运行刷新按钮与结果容器使用了相同标记，刷新会覆盖按钮；候选包已修正并重新校验内容摘要。
- 候选元数据更新了单文件摘要但遗漏汇总摘要；现明确汇总算法并在候选检查中验证一致性。
- 绘制循环在第一帧耗尽 10000 条 trace 额度。现在同一节点、事件类型、tick/frame 只保留前八次，后续不同节点与时刻仍可记录；总量仍受 10000 条/4 MiB 上限约束。所有省略计入 truncation，已有记录只追加，不能把保留条数或耗时解读为完整累计值。
- 固定输入回放只入队而没有推进到目标 tick。共享执行器现在实际推进固定时钟。预览启动消息增加经过严格布尔校验的可选 `paused` 控制，仍使用原授权计划与模拟时钟；省略时保留原启动行为。G09 从暂停的 tick 0 启动，再主动步进至 tick 2 后输入，不再依赖跨窗口暂停消息的到达速度。
- 当前证据的输入绑定补充了 `evals` 的执行器、回放数据、schema 与测试；新增回归验证这些文件变化会使摘要失效。安全源检查同步到实际稳定 ID 解析变量，保留原安全约束。

## 游戏与性能证据的范围

七类游戏使用保存的 M12 项目副本与其原 simulation seed/rate。G09 的短输入与预期事件冻结在 `apps/ai-studio/test/m14-integration/gameplay-replays.json`；每个预期事件必须在真实状态中出现，并对应实际执行的精确脚本位置。俄罗斯方块原样例调用运行环境不存在的全局输入函数，只在独立副本中替换为公共 `api.input`，同时记录前后脚本摘要。它的移动/旋转没有命名遥测，必须同时证明真实输入分支为真和实际状态变化。历史项目、M12 全游戏 replay 与验收状态均未修改。

每个游戏运行两次真实 Electron/WebGPU Play，比较全部采样状态，校验脚本摘要/源位置，确认原 Document 不变，并验证 Stop 后 disposableCount 为零。截断信息与原始观察保存在 `test-output/gameplay`；旧失败单独归档到 diagnostics，不作为通过证据。

规模测试固定为 i7-7700、8 逻辑线程、Windows 10.0.19045、GTX 1070 Ti；预算文件在测量前冻结。1000 个实体/200 个脚本验证的是文档、树、查询、选择和面板反复挂载，不代表同时运行 200 个脚本或渲染 1000 个网格。手工工具不伪造 Agent 会话记录，产品重启样例的 Agent 记录数为零；项目 Agent 完整记录的切换、复制与恢复由专门的持久化/协调测试验证，窗口记录查看器测试使用明确的 UI fixture。

当前测量：打开项目 295 ms，高级面板挂载 313 ms，筛选并选择末尾实体 84 ms，资源查询 735 ms；五次关闭/重开面板后 renderer 堆从 7,988,848 增至 8,211,952 字节，均在冻结预算内。生产扫描 143 个文件通过，当前完整检查扫描 605 个文件通过；生产没有生成 crash dump。逐项审计另有覆盖新增证据的补充扫描。

## 验证入口与准入

`npm run check` 包含资源、公共高级适配、真实设备、七类游戏、生产窗口、项目记录与安全检查。新增嵌套目录必须与 `scripts/m14-integration-tests.json` 的冻结文件清单一致；每个文件的真实测试数量、失败/跳过数量和日志路径保存在 `test-output/collected-tests.json`。检查前后完整输入摘要必须相等。扫描覆盖本次临时项目、生成的 app user-data/journal/artifact、已有 crash dump、renderer DOM/公开投影及输出文件；不读取真实凭据文件，零 crash dump 明确表示未生成 dump。

六层关联目前分别由候选及锁（upstream）、原 Document/History（document）、真实 Play/设备（runtime）、原通用工具和审批（tool）、生产窗口公共入口（ui）及当前完整检查（verification）提供。真实双后端结果尚缺，`product-integrated` 不提升，G09 不标记完成。`live-backends.mjs` 只在获得所述在线数据发送授权后运行；既有凭据就绪不等于授权，确定性 transport 测试也不能替代在线证据。
