# 任务内脚本提交与预览授权

2026-09-15，按用户要求调整此前逐次审批脚本提交的产品策略：批准规划包含同一任务内的项目脚本编写和提交。首次执行新代码仍单独授权。此策略更新 M06 的逐次人工 trusted-code 确认方式，不取消工具层校验或运行授权。

## 责任边界

- `script.propose` / `script.patch` 仍仅生成和校验提案。`script.apply` 在 Host 已批准规划、已批准 turn、当前 document 一致时，由规划授权形成当前精确操作的 `allow-once` 决定。记录 `conversation/plan-script-authorized`（任务、文档、修订、参数和预览摘要），无需暂停模型再次等用户点击。没有批准规划的直接工具调用仍遵守原审批策略。
- 本策略不扩展 Node、文件、网络或其他运行权限，也不自动启动项目脚本。校验失败、过期修订和目标冲突仍阻止提交；History 路径不变。
- `play.start` / `preview.start` 的 schema 只有 `baseRevision` 和已验证的 `planId`。重新验证可能生成新的计划句柄，而执行内容不变。尚未消费的持久批准可在同一任务、文档、工具版本、目标、修订、风险和预览摘要完全相同时，绑定新句柄形成一次授权。预览摘要包含执行脚本集合摘要；不能把这项规则推广到其他工具。
- 成功执行后的重复预览，使用 `PreviewAuthorizationService.canReuse` 的既有用户授权：同一文档、脚本内容/顺序/归属/能力和运行配置。几何等静态场景变更无需重新批准代码，但每次启动仍准备当前精确修订，并创建和消费新的一次性运行 grant。
- 在 prepare 和 execute 时均检查可复用授权。撤销、新代码、新权限、运行配置变化或缺失可信本地授权事实时，回退人工授权。已消费的恢复授权不能再次消费。
